# Plan — The workout on the Apple Watch

Owner decision (2026-10-16): **Level 1 now, Level 2 next.** Both are planned
here; the tasks ship Level 1 as its own slice first, then Level 2 in separate
commits that stay inert until the device rebuild.

## Current state (verified 2026-10-17, branch `feat/sdd-batch`)

- The Live Activity (spec 0012) is an `ActivityConfiguration` for
  `WorkoutActivityAttributes` in `apps/mobile/targets/workout-activity/`
  (widget extension, deployment target iOS 17.0, generated by
  `@bacons/apple-targets` 5.0.0). It has a lock-screen view and the Dynamic
  Island regions; the rest countdown of 0018 is `restEndsAt` +
  `staleDate`/`isStale`.
- It declares no `supplementalActivityFamilies`. On iOS 18 + watchOS 11 the
  system already mirrors every Live Activity to the paired watch's Smart Stack,
  but without that declaration it builds the watch view from the **compact
  Dynamic Island leading/trailing** views only: an icon plus the clock or the
  rest — no routine name, no calories, never both clock and rest. AC-1 is not
  met today.
- No watch target, no WatchConnectivity, no HealthKit workout session. The
  phone reads calories with an `HKStatisticsQuery` (spec 0012) every 60 s in
  the foreground; `syncWorkoutCompletionToAppleHealth` is a stub, so the app
  writes no workout to Health today.
- Ticking a set on the phone: `ActiveWorkoutScreen.handleToggleDone` →
  `toggleWorkoutSetDone` + `startRest(resolveRestSeconds(…))` (spec 0018).
- Xcode 26.6 with the iOS 26.5 and watchOS 26.5 SDKs is installed, so Swift
  can be type-checked locally; nothing can be run on a device here.

## Level 1 — the Live Activity on the watch's Smart Stack

### Approach

- `ActivityConfiguration(…)` gains `.supplementalActivityFamilies([.small])`
  (iOS 18). The widget extension keeps its iOS 17.0 deployment target: the
  modifier is applied in a `WidgetConfiguration` extension whose `some`
  result returns different types under `if #available(iOS 18.0, *)` (Swift's
  limited-availability opaque results, SE-0360).
- The lock-screen closure renders a `FamilyAwareView`: on iOS 18 it reads
  `@Environment(\.activityFamily)`; `.small` → new `WatchSmallView`, anything
  else → the existing `LockScreenView` (iPhone lock screen unchanged).
- `WatchSmallView` (read-only, as the spec says):
  - row 1: dumbbell + routine name (one line), "Paused" in the accent colour
    when paused;
  - row 2: the elapsed clock, large (`ElapsedText`, same system timer);
  - row 3: the rest countdown with the timer symbol (`RestCountdown`) while a
    rest runs and is not stale, and the calories when known.
  No buttons: Pause/Resume/Finish stay on the phone surfaces.
- Calories: shown only when known in the small view (FR-1 "when known");
  `[ASSUMPTION: the watch's small view hides unknown calories instead of
  "— kcal", to save its tiny space; the iPhone views keep "— kcal".]`
- The rest-end buzz on the watch is 0018's local notification, which iOS
  forwards to the watch while the phone is locked. Nothing new.
- No change to `WorkoutActivityAttributes` (both copies stay identical), the
  module, the JS or `app.json`.

### Alternatives considered

- **Leave the system default (compact views)** — rejected: shows icon + one
  number; AC-1 needs routine, clock and rest together.
- **Raise the widget extension to iOS 18** — rejected: would silently drop the
  Live Activity on iOS 17 phones; the availability-guarded modifier costs a
  few lines.
- **A `.medium`-style reuse of the lock-screen view on the watch** — rejected:
  the lock-screen view carries buttons and four rows; it does not fit.

## Level 2 — a watch app

### Approach

The phone stays the source of the logged data; the watch mirrors it and sends
requests back.

**Transport: WatchConnectivity + HealthKit's "start the watch app".**

- *Phone → watch, state:* `WCSession.updateApplicationContext` with one JSON
  string (`context`): workout id, routine name, start, pause, paused seconds,
  rest end, the current set (exercise name, "Set 2 of 4", target text
  "60 kg × 8", the rest it starts), the labels in the app language, and a
  status (`active` / `finished` / `discarded`). Latest wins, delivered when
  the watch app next runs — exactly "mirror the state".
- *Phone → watch, start (FR-2):* `HKHealthStore.startWatchApp(with:)` with an
  `HKWorkoutConfiguration` (traditional strength training, indoor), only when
  `WCSession.isWatchAppInstalled`. The system launches the watch app, which
  starts its workout session in `WKApplicationDelegate.handle(_:)`.
- *Watch → phone, requests:* `WCSession.transferUserInfo` with one JSON
  string (`event`): `setDone` (exercise id, set id, instant), `pause`,
  `resume`, `finishRequested`. The system queues them, survives lost contact
  and delivers **in order** (EF-1). Each carries a unique id; applying is
  idempotent (a set already done stays as is), so a replay is harmless.
- *Watch → phone, calories (FR-3):* the watch's own application context
  (`metrics` JSON: workout id, kcal) — latest wins.

**Watch app (`targets/watch/`, `type: 'watch'`, watchOS 11.0):**

- `HKWorkoutSession` + `HKLiveWorkoutBuilder` with
  `HKLiveWorkoutDataSource`. Collection starts at the **phone's start
  instant**, so the workout in Health spans the same time as the app's. Heart
  rate (most recent) and active energy (sum) come from the builder's
  statistics — continuous measurement (FR-3, AC-2).
- On `finished` the builder ends collection and saves the workout to Health
  (FR-5: the phone writes none — `syncWorkoutCompletionToAppleHealth` stays a
  stub — so there is exactly one); on `discarded` it discards it.
- Authorization asked on the watch: share workouts + active energy, read heart
  rate + active energy. No heart-rate data → heart rate hidden, never 0 (EF-2).
- One screen: routine, elapsed clock, heart rate, kcal, rest countdown, the
  current exercise + set + target, **Done**, Pause/Resume, Finish. Done marks
  the set locally at once, starts the local rest with the set's rest seconds,
  and queues `setDone`; a haptic (`WKInterfaceDevice.play(.stop)`) when the
  rest ends. The next context from the phone replaces the local guess.
- Pause/Resume pause the watch session and queue the request; the phone's
  next context is authoritative (the session follows `pausedAt`).
- **Finish on the watch asks the phone**: `finishRequested` opens the phone's
  active workout with the existing `action=finish` confirmation (spec 0012).
  `[ASSUMPTION: the watch never finishes or saves on its own — the owner
  rejected finishing in the background in 0012, and a save needs the phone's
  network; the watch session ends when the phone finishes.]`
- With a context `active` but no session (e.g. the app opened by hand, or
  `startWatchApp` not delivered), the watch starts the session itself.

**Phone (`apps/mobile`):**

- Local module `modules/watch-workout` (iOS): activates `WCSession`;
  `isWatchAppInstalled()`, `startWatchApp()`, `sendContext(json)`;
  event `onMessage({ kind: 'event' | 'metrics', json })` from received user
  info and application context, **buffered until JS listens** (user info
  queued while the app was closed arrives at activation).
- `features/workouts/watch/watchProtocol.ts` (pure): `currentSetToDo(draft)`,
  `toWatchSnapshot(draft, defaultRestSeconds)`, `parseWatchEvent(json)`,
  `applyWatchEvent(draft, event, defaultRestSeconds)`. `setDone` reuses a new
  store helper `completeSet(draft, exerciseId, setId, defaultRestSeconds, at)`
  — the same rule the screen uses (FR-1 of 0018), with the rest's end counted
  from the tick's instant, so a tick delivered late starts a rest that may
  already be over (0018's runner then clears it as stale, no alert).
  `ActiveWorkoutScreen.handleToggleDone` uses `completeSet` for the
  done-direction, so phone and watch tick identically.
- `features/workouts/watch/watchWorkoutController.ts`: subscribes to the draft
  store; start on a new workout identity, update on any change of the
  snapshot, end on clear with `finished` when `getLatestCompletedWorkout()`
  is that workout, else `discarded`. Events for another workout are dropped;
  `finishRequested` → callback; `activeEnergy` → callback.
- Wiring in `useLiveWorkoutController`: once the watch reported kcal for the
  current workout, the Live Activity and the in-app figure use the watch's
  value and ignore the phone's own Health query for that workout (FR-3);
  `finishRequested` → `router.navigate('/workouts/active?action=finish')`.

### Alternatives considered

- **HealthKit workout mirroring (`startMirroringToCompanionDevice`, iOS 17)** —
  the Apple-recommended channel, and it keeps the phone app running while
  mirrored. Rejected for now: the phone's mirroring handler must be installed
  at app launch (AppDelegate), before React Native loads, which needs an Expo
  AppDelegate subscriber; and the delivery is not queued when contact is lost,
  so EF-1 would need our own queue anyway. Worth revisiting if the device test
  shows that queued user info arrives too late (`TODO(sdd)` in Risks).
- **The watch writes ticks to Health / the API directly** — rejected: the
  phone is the source of logged data (spec), and the watch has no session
  token.
- **The watch saves the workout itself on Finish** — rejected (see the
  assumption above).
- **`sendMessage` for ticks** — faster when reachable, but not queued and not
  ordered with `transferUserInfo`; one ordered channel is simpler (EF-1).

## Shared contracts (`packages/domain`) — Level 2 only

In `health.ts`:

```ts
export interface WatchWorkoutSnapshot {
  workoutSessionId: string;
  routineName: string;
  startedAt: ISODateString;
  pausedAt?: ISODateString;
  pausedSeconds: number;
  restEndsAt?: ISODateString;
  /** The set to do now, display-ready; absent when every set is done. */
  currentSet?: {
    workoutExerciseId: string;
    workoutSetId: string;
    exerciseName: string;
    setNumber: number;
    setCount: number;
    /** Planned values as shown on the phone, e.g. "60 kg × 8"; empty when none. */
    target: string;
    /** The rest ticking this set starts, in seconds (0 = none). */
    restSeconds: number;
  };
}

export type WatchWorkoutEvent =
  | { kind: 'setDone'; id: string; workoutSessionId: string; workoutExerciseId: string; workoutSetId: string; at: ISODateString }
  | { kind: 'pause' | 'resume'; id: string; workoutSessionId: string; at: ISODateString }
  | { kind: 'finishRequested'; id: string; workoutSessionId: string }
  | { kind: 'activeEnergy'; workoutSessionId: string; kcal: number };

export interface WatchWorkoutBridge {
  providerId: HealthProviderId;
  startWatchWorkout(snapshot: WatchWorkoutSnapshot): Promise<void>;
  updateWatchWorkout(snapshot: WatchWorkoutSnapshot): Promise<void>;
  endWatchWorkout(workoutSessionId: string, outcome: 'finished' | 'discarded'): Promise<void>;
  onWatchWorkoutEvent(listener: (event: WatchWorkoutEvent) => void): () => void;
}
```

Impact: `apps/api` none; `apps/mobile` gains the adapter and the controller.

  device shows it. Level 1: the small family layout on a 49 mm Smart Stack.
  Level 2: everything native.
- **Free team and the watch app.** One more App ID (10 per 7 days) and a
  7-day profile for the watch too. HealthKit on the watch with the free team is
  expected to sign like on the phone (verified there in 0012) but unproven.
  `TODO(sdd): confirm on the first signed build that the watch app signs with

  a paid team (owner decision).`
- **Installing the watch app.** `xcrun devicectl device install app` installs
  on the phone; the embedded watch app installs through the Watch app's
  automatic install, or directly with `devicectl` on the watch's device id.
  `TODO(sdd): record the exact steps in the README after the first install.`
- **Phone app in the background.** Queued user info reaches the phone app when
  it next runs; with the phone in a bag the tick may only show on the phone
  when it is opened (the rest then counts from the tick's instant). If that is
  too late in practice, switch the channel to HealthKit workout mirroring
  (alternative above). `TODO(sdd): measure on the device.`
- **Double haptic at rest end.** The watch buzzes itself and 0018's phone
  notification is forwarded to the watch when the phone is locked.
  `TODO(sdd): if both arrive, skip the phone's rest notification while a
  watch workout runs.`
- **Two calorie sources.** Before the watch sends its first value the phone
  shows its own Health query; then the watch's figure. Once the watch has
  reported for a workout, the phone's query is ignored for it.
- `@bacons/apple-targets` marks `watch` as supported, but this project has not
  generated one before; the unsigned simulator build is the first check.
